## 关于Carson

> Carson永远沉溺于过去和未来。

或许Carson很早就习惯了这种悬置感,或者说很多时候，他并不活在一个确定的当下

过去在他身上留下痕迹，未来向他投来影子，而现在常常只是两者短暂交汇的一小块地面。他站在上面，停留，观察，记录，然后继续往前。

已经发生过的事情容易把他拉回过去，而那些尚未到来的生活，也总是会提前占据一些注意力。过去留下痕迹，未来映射出一些xx，现在对于他来说，则像是两者之间一小块短暂露出的地面。他站在上面，观察，记录，偶尔迟疑，然后慢慢继续往前走。

他学软件工程，也因此习惯从一种理性的角度来理解世界，可是他却不那么认为。

系统、结构、逻辑、MVP、Agile、Sprint，这些东西塑造了他思考问题的一部分方式。但后来，他慢慢发现，比起一个系统理论上能够做什么，自己似乎更在意它真正落到人手里以后会发生什么。

一个按钮为什么让人犹豫，一段反馈为什么令人安心，一个本来逻辑完整的流程为什么到了现实里突然变得难以使用——技术在纸面上通常很整齐，可一旦进入生活，就会开始变形。人的理解、习惯、注意力和情绪都会进入其中。技术在纸面上总是整齐的，落到真实生活里却会变形，会沉默，会暴露出许多更细微的问题。那些问题后来比答案更吸引他。

他曾经也被更大的叙述打动过。

那些关于方向、时代、效率、变革的词语。只是慢慢地，他对宏大的句子变得谨慎起来，他开始更相信局部，相信细节，相信那些不那么响亮却更贴近人的时刻。一个界面是否清晰，一段反馈是否温和，一种交互是否真的照顾到了使用者的犹豫与专注？这些问题在他心里的分量一点一点变重。比起谈论技术将把人带向哪里，他更关心技术此刻如何与人相处。

有一段时间，他把自己放进真实的教学现场里。课堂、讲台、屏幕、教师的话语、学生的目光、那些顺利与不顺利的瞬间，共同构成了一种与想象完全不同的密度。很多抽象的判断在那里被重新校准。技术并不会因为名字新、概念宏大就自动成立，它需要被理解，被信任，被纳入使用者的工作节奏；它也需要承受误差、摩擦和现实的迟缓。那段经历后来渐渐成为一段已经合上的章节，已经翻过去的生活。

于是他的目光开始向内收，也向近处移动。他更愿意把注意力放在界面、感知、学习过程，以及人与工具之间那些微妙的接缝上。他开始对"如何设计一种不打断人的技术"这样的问题生出兴趣，也反复想着，什么样的产品能够有效地帮助人，同时保留某种朴素的分寸感。他所寻找的，越来越是一种准确。

他的性格里始终有两股并行的力量。一股把他推向秩序与结构，推向那些可以被拆解、被重新搭建的东西；另一股把他推向更难命名的部分——情绪、记忆、那些尚未说清但真实存在的感受。他听很多Post Rock和Shoegaze，也乐于制造一点属于自己的声音；他会为某些球队的胜负牵动情绪，也会因为一本书里的某一句话停下来很久。看上去互不相关的事物，最后都在他身上汇成同一种倾向：他对"人是如何感受世界的"始终怀有耐心。

Carson并不急于把自己定义得太完整。完整有时意味着被固定，而他还愿意保留一些未完成。他似乎更习惯于在很多个方向之间缓慢移动：在技术和表达之间，在理性与敏感之间，在已经经历过的生活与尚未抵达的地方之间。他正在慢慢接纳这种移动，也逐渐学会从中辨认自己。

他喜欢那些真正有用的东西。经过思考之后仍然显得克制、平静、顺手的设计。一个好的工具应该让人感觉自己被理解，帮助人把注意力放回问题本身。这种偏好延伸到了他看待许多事物的方式里：他偏爱有边界感的表达，偏爱那些说到恰好为止的句子。

至于未来，他依然会想得很多。那种对远方的感受并没有消失，只是变得比从前更安静了一些。它不再总是以宏大的想象出现，更多时候，它藏在一些很小的愿望里：希望自己能继续靠近真正重要的问题，继续在技术与人之间寻找一种更长久的平衡，在每一次构建与每一次书写里，把模糊的感受慢慢整理清楚。

如今，他已经在 KTH 的 Interactive Media Technology 项目里继续自己的下一段学习。那并不只是一次地理意义上的迁移，更像是他此前那些兴趣与犹疑、结构与感受、技术与人的问题，终于在另一座城市、另一种媒介语境里，找到了继续生长下去的空间。

过去那个遥远的“以后去斯德哥尔摩”，已经变成了每天需要真正生活的城市。

早晨从 Lappis 出门，经过熟悉的路去学校；在地铁、公交和步行之间观察人们如何移动；坐在 KTH 的教室、工作室和图书馆里讨论设计、研究与技术；傍晚再沿着已经渐渐熟悉的路线回去。

斯德哥尔摩并没有一直以“新城市”的姿态存在。

住得稍久一些以后，它也开始出现一些普通得不能再普通的部分：超市里的价格标签、公共厨房里没有洗掉的盘子、突然下起的雨、错过的一班车、越来越早落下来的天色，以及每周重复经过很多次的街道。

恰恰是这些东西，让一座原本只存在于地图和想象里的城市慢慢获得了重量。

他也逐渐发现，自己来到这里之后真正感兴趣的东西，与过去并没有断裂。

而过去也不会真的离开。他仍然会反复回望一些阶段、一些城市、一些相遇、一些曾让他确信自己正在靠近某种真实的瞬间。只是如今的回望里少了一点执拗，多了一点理解。那些已经结束的部分并没有消失，它们只是沉到更深处，成为了他观看世界的方式，成为了他面对新事物时的底色。

"Carson永远沉溺于过去和未来。"

只是现在，他也开始愿意把更多目光留给那些具体的人、具体的界面、具体的时刻。宏大的叙述渐渐退到远处，真正留在手边的，是一次次更小、更近、也更诚实的接触。对他来说，很多事情正是从这里开始变得重要。

## 关于Coding

对 Carson 来说，Coding 是一种组织复杂性的方式。

他以 Python 为主要语言，长期用于数据分析、机器学习与实验验证；也使用 JavaScript / TypeScript 与 React 进行前端开发，关注页面结构、组件逻辑与交互节奏。

在机器学习与深度学习方向，他接触过从传统模型到神经网络模型的一系列方法，包括 SVM、XGBoost、CNN、RNN、GNN 与 Transformer，也使用过 PCA、LASSO、SHAP、Grad-CAM、LIME 等方法进行特征处理、模型解释与结果分析。

在生成式 AI 方向，他关注 Prompt Engineering、RAG、Agent 与 AI 应用编排，也尝试过 Dify、Coze、LangChain、AutoGen Studio 等工具。

相比单纯调用一个更强的模型，他更关心 AI 如何进入真实任务流程：它在哪里真正有帮助，在哪里容易制造新的复杂性，又怎样才能被组织成稳定、可理解、能够长期使用的产品能力。

最近他在学习 Harness Engineering，也就是模型之外的那一层：上下文如何被组织，工具与权限如何被给出，一次任务在什么边界里循环、在哪里应该停下。模型本身的强弱之外，这些安排往往才决定了它在真实工作里是否稳定、是否可被信任。

来到 KTH 之后，他也开始把更多注意力放在人机交互与交互设计上。

研究方法、用户观察、访谈、Coding、Affinity Diagram、Persona、Scenario、Prototype，这些过去相对陌生的方法，逐渐成为理解产品的另一种语言。

Figma、Axure、XMind，以及过去接触过的 SWOT、KANO 模型与用户体验方法，则连接起了他在技术、产品与设计之间的不同经验。

代码在他这里最终还是会通向一些更具体的东西：

界面、体验、产品，以及人与技术之间那些微妙的接缝。

## 关于本站

这个网站是 Carson 为自己留下的一处缓慢更新的空间。

它不是作品集的陈列柜，也不只是简历的网页版本。

它更像一个可以不断修改的个人界面，用来放置文字、项目、实验、照片、声音，以及一些暂时还没有被整理成明确结论的想法。

本站目前基于 React / TypeScript 构建，以组件化的方式组织页面，并使用 Framer Motion 处理一些细微的动效与转场。

视觉上，他希望它尽量保持安静：较窄的正文栏、足够的留白、清晰但不过分强调的层级，以及少量带有叙事意味的交互细节。

Carson 希望它看起来不像一个急着证明自己的地方。

更像一间仍然有人住、也仍然在整理中的房间。

这里会有技术，也会有文字；会有已经完成的项目，也会留下尚未完成的观察。

以前，这个网站更多记录他如何想象下一站。

现在，其中也开始出现斯德哥尔摩的天气、KTH 的课程、Lappis 的生活、设计项目里贴满墙面的便签，以及一些发生在异国生活中、原本没有计划记录的小事。

它记录一个人怎样使用工具，怎样理解世界。

也记录一个曾经总把目光投向过去和未来的人，如何一点点学会把自己安放在正在发生的生活里。
